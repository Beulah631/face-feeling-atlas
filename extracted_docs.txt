ABSTRACT
Facial emotion recognition has become an essential component of
human– computer interaction because the emotional state of a
person, conveyed through the face, is one of the most immediate and
universal channels of non-verbal communication.
Conventional recognition pipelines rely on convolutional neural
networks (CNN) operating on small, low-resolution grayscale faces,
and although such pipelines are computationally cheap, their
accuracy saturates because a fixed convolutional kernel can model
only a limited receptive field and cannot capture the long-range
spatial dependencies that exist between distant facial regions such as
the eyes and the mouth.
This project presents an improved facial emotion recognition system
that combines a CNN baseline with a Swin Transformer classifier
and YOLOv8based face detection. The system first localises faces in
an input image using the anchor-free YOLOv8 detector.Each
detected face is then classified into one of seven emotion categories
(Angry, Disgust, Fear, Happy, Sad, Surprise and Neutral) by two
alternative models: a compact CNN operating on 48 × 48 grayscale
images and a hierarchical vision Transformer (Swin Transformer)
operating on 224 × 224 × 3 colour images, obtained through the
timm model library.
The two models are trained and evaluated on the public FER2013
dataset, and their comparative behaviour in terms of accuracy, per-
class behaviour and inference cost is studied.
The recognition pipeline is exposed as a service through a FastAPI
backend and consumed by a React, TypeScript, Vite and Tailwind
CSS front end, so that a user can upload a photograph or use a
camera frame and immediately observe the detected emotion.

CHAPTER 1
INTRODUCTION
1.1 General
Facial emotion recognition is an important research area in artificial
intelligence, computer vision, and human-computer interaction. It
focuses on identifying human emotional expressions by analysing facial
features present in an image or video. Facial expressions provide
valuable information about a person’s emotional state and can support
the development of intelligent systems that interact more naturally with
humans. Emotions such as happiness, sadness, anger, fear, surprise,
disgust, and neutrality can be recognized by examining variations in the
eyes, eyebrows, mouth, and other facial regions.
Traditional emotion recognition systems often depend on manually
designed facial features and conventional machine learning algorithms.
Although these approaches can perform well under controlled
conditions, their performance may be affected by variations in lighting,
facial orientation, image quality, occlusion, and differences between
individuals. Deep learning has improved facial emotion recognition by
enabling models to learn useful visual representations directly from
image data.
Convolutional Neural Networks (CNNs) are widely used for image
classification because they can learn spatial patterns such as edges,
textures, and facial structures. However, CNNs primarily learn local
visual features through convolution operations, which may limit their
ability to represent relationships between distant regions of an image.
Transformer-based architectures provide an alternative by modelling
relationships between different image regions. The Swin Transformer
xi
---PAGE 12 (1614 chars)---
uses hierarchical feature representations and shifted-window attention to
capture visual information at multiple levels.
In this project, an improved facial emotion recognition system is
developed by combining face detection with emotion classification. The
YOLOv8 model is used to detect faces in an input image or video frame,
while CNN and Swin Transformer models are considered for emotion
classification. Their performance can be compared using the same
dataset and evaluation conditions. The system is designed with a web-
based interface supported by a Python backend, allowing users to
provide visual inputs and obtain emotion predictions.
The main purpose of the project is to examine how a Transformer-based
classification approach compares with a CNN-based approach within a
practical facial emotion recognition pipeline.
1.2 Background of the Study
Human facial expressions are an important component of non-verbal
communication. People frequently use facial expressions to
communicate feelings and reactions without speaking. Automatically
recognizing these expressions can help computer systems interpret visual
information and support applications such as interactive interfaces,
educational tools, behavioural research, and other emotion-aware
systems.
The development of automatic facial emotion recognition has
progressed from handcrafted feature extraction to deep learning-based
methods.
CNN-based approaches introduced an effective method for learning
facial features automatically from labelled images. By applying multiple
convolutional and pooling layers, CNNs can learn representations
xii
---PAGE 13 (1791 chars)---
ranging from simple visual patterns to more complex facial
characteristics. Their ability to learn features directly from data makes
them suitable for classifying facial expressions. However, distinguishing
between visually similar emotions may remain challenging, particularly
when images contain low-resolution faces, ambiguous expressions, or
variations in lighting and pose.
Face detection is another important component of an emotion
recognition system. Before an expression can be classified, the system
must locate the face within the input image. YOLOv8 is an object-
detection architecture designed to identify objects and estimate their
locations efficiently. In the proposed pipeline, it is used for face
detection, after which the detected facial region can be prepared for
classification by the CNN or Swin Transformer model.
The FER2013 dataset is used in this project as the source of facial
expression images. It contains examples labelled across seven emotion
categories: Angry, Disgust, Fear, Happy, Sad, Surprise, and Neutral. The
dataset provides a common basis for training and evaluating emotion
classification models. The CNN model uses 48 × 48 grayscale images,
whereas the Swin Transformer uses 224 × 224 × 3 input images.
Appropriate preprocessing is therefore required to prepare the dataset for
each model.
1.3 Problem Statement
Automatic facial emotion recognition remains challenging because
facial expressions vary between individuals and are influenced by
lighting conditions, image resolution, head orientation, partial occlusion,
and the intensity of the displayed emotion. A system must first identify
the face accurately and then classify its expression. Errors during face
detection or image preprocessing can affect the final classification result.
xiii
---PAGE 14 (1341 chars)---
CNN-based models provide an effective baseline for facial emotion
classification, but their feature extraction process may not capture every
relationship between distant facial regions. Therefore, the problem
addressed in this project is the development of a practical facial emotion
recognition pipeline that combines face detection using YOLOv8 with
emotion classification using CNN and Swin Transformer models. The
system aims to support a fair comparison of the two classification
approaches using the FER2013 dataset and a web-based application
interface.
1.4 Aim of the Project
The primary aim of this project is to develop a facial emotion
recognition system using YOLOv8 for face detection and to compare
CNN-based emotion classification with Swin Transformer-based
classification. The system uses the FER2013 dataset, suitable image
preprocessing, and an integrated software interface to support emotion
prediction and model evaluation.
1.5 Objectives of the Project
The key objectives of the proposed system are as follows:
1. To develop a facial emotion recognition system using YOLOv8 for
face detection and Swin Transformer for classifying seven emotions
using the FER2013 dataset.
2. To compare the proposed Swin Transformer model with the
existing CNN-based system and evaluate their performance using
appropriate metrics.

1.6 Scope of the Project
The scope of this project covers the design, implementation, and
evaluation of a facial emotion recognition system using deep learning
and computer vision techniques. The system focuses on detecting faces
and classifying the expressions into seven predefined emotion categories
using the FER2013 dataset.
YOLOv8 is used for face detection, while CNN and Swin Transformer
models are used as alternative emotion classifiers. The CNN processes
48 × 48 grayscale images, whereas the Swin Transformer processes 224
× 224 × 3 images. These input requirements involve different
preprocessing procedures, which must be applied consistently during the
respective model workflows.
The comparative study focuses on the behaviour of the CNN and
Swin Transformer classifiers when used for facial emotion recognition.
Any performance conclusions must be based on the actual experimental
results obtained during testing. The project does not assume that one
model is superior without supporting evidence.
1.7 Significance of the Project
The significance of this project lies in combining face detection and
deep learning-based emotion classification within a single application.
By separating face detection from emotion classification, the system
provides a clear processing pipeline in which each stage has a specific
role. YOLOv8 identifies the facial region, while the CNN or Swin
Transformer analyses the detected face to predict an emotion category.
The comparison between CNN and Swin Transformer models is useful
for understanding two different approaches to visual feature learning.
CNNs learn spatial features through convolution operations, while the
xv
---PAGE 16 (1238 chars)---
Swin Transformer uses attention mechanisms and hierarchical
representations to model relationships between image regions.
Evaluating these approaches under consistent conditions can help
identify their practical advantages and limitations for the selected dataset
and task.
The use of the FER2013 dataset establishes a common set of emotion
categories for the classification process. Applying suitable preprocessing
for each architecture also highlights the importance of input preparation
when comparing models with different design requirements.The
integration of the models with a FastAPI backend and React-based
frontend demonstrates how deep learning models can be incorporated
into an accessible software application. This structure separates the user
interface from the model-processing components and provides a
foundation for testing the system through a web interface.
Overall, this project provides a structured implementation and
comparison of CNN-based and Swin Transformer-based facial emotion
classification, supported by YOLOv8 face detection and a web
application. Its significance is the integration of these components and
the opportunity to evaluate the approaches using the project’s actual
experimental evidence.

CHAPTER 2
LITERATURE SURVEY
2.1 General
A survey of twenty-eight research papers was carried out using IEEE
Xplore, the ACM Digital Library, Springer, Elsevier and the arXiv pre-
print server. The papers span the period from the introduction of large-
scale deep FER on FER2013 to recent Transformer-based facial-analysis
studies, and were selected because they report measured results on
public facial datasets, cover either face detection or emotion
classification, or define the architectural families compared in this
project.
The common trend across the survey is a steady migration from hand-
crafted features to deep CNNs and, more recently, to hierarchical vision
Transformers, together with a growing insistence that models be
evaluated on realistic, automatically detected faces rather than on pre-
cropped images. A second, quieter trend is the appearance of deployable
implementations:
The newest papers increasingly report inference speed and model size
alongside accuracy, acknowledging that a model must run somewhere.
This chapter is organised into a review of literature, presented theme by
theme, followed by the research gap that emerges from the review.
The selection criteria were applied in three steps. Papers were first
collected with the keywords facial expression recognition, FER2013,
Swin Transformer, vision transformer and YOLO; they were then filtered
to retain only works that report quantitative results on public data or
define the architectures under study; and finally each retained paper was
summarised with its method, dataset, reported result and limitation.

2.2 Review of Literature
2.1 Facial Emotion Recognition
[1] Canal et al. (2022) reviewed facial emotion recognition
techniques using a systematic literature review of 51 selected studies
covering 94 approaches. The review discussed traditional machine
learning and neural-network methods for facial expression classification.
It identified the increasing use of CNN-based approaches. A major
challenge remains reliable recognition under different real-world
conditions.
[2] Khan (2022) reviewed conventional machine learning and deep
learning techniques for facial emotion recognition. The study discussed
datasets, evaluation methods, and the strengths and limitations of
different approaches. It highlighted the importance of selecting suitable
datasets and evaluation metrics. Its broad review does not implement a
single integrated detection and classification system.
[3] Rathour et al. (2022) examined the development of facial emotion
recognition, including face detection, feature extraction, and expression
classification. The review considered CNNs, deep belief networks,
autoencoders, and recurrent neural networks. It identified dataset
limitations, bias, and model integration as continuing challenges. As a
survey, it does not provide a new experimental model.
[4] Kopalidis et al. (2024) presented a comprehensive survey of facial
expression recognition methods, datasets, and benchmarks. The authors
discussed deep-learning methods and challenges such as overfitting,
illumination changes, head pose, and identity bias. Their review provides
useful guidance for selecting datasets and evaluation approaches.
However, it does not establish which classifier is best for every
application.

2.2 CNN in Facial Emotion Recognition
[6] Zhao, Liu, and Zhou (2021) proposed EfficientFace, a
lightweight facial expression recognition network using local-feature
extraction, channel-spatial modulation, and label-distribution learning.
The model was evaluated on RAF-DB, CAER-S, and AffectNet datasets.
It reported accuracies of 88.36%, 85.87%, and 63.70%, respectively, on
the corresponding benchmarks. Its performance can still be affected by
dataset characteristics and challenging facial expressions.
[7] Li (2021) investigated facial expression recognition using transfer
learning with a ResNet-101 architecture. The study reported an overall
accuracy of (96.29 \pm 0.78%). Transfer learning allows a model to
reuse features learned from earlier training, reducing the need to learn
every visual representation from scratch. However, the result should be
interpreted according to the study’s experimental setup and dataset rather
than directly compared with results from different benchmarks.
[8] Authors of “Facial Emotion Recognition (FER) using
Convolutional Neural Network” (2024) explored deep CNNs and
pretrained architectures, including EfficientNet, ResNet, and VGGNet,
for facial emotion classification. The study used the FER2013 dataset
and reported approximately 82% accuracy on its training data. The work
demonstrates the use of CNNs for facial emotion analysis. However,

[9] Xue, Wang, and Guo (2021) introduced TransFER, a Transformer-

uses attention-dropping mechanisms and a Vision Transformer
component to improve representation learning. The work addresses the
difficulty of recognizing expressions when important facial regions are
obscured or affected by pose changes. Its performance depends on the
quality of the learned representations and the data used for training.
[10] Li et al. (2023) proposed a region-attention network (RAN) for

informative facial regions and was evaluated on in-the-wild facial

detection model through the Ultralytics implementation. Its detection
architecture can locate objects in images and video frames, making it
suitable as a face-localization component in a facial emotion recognition
pipeline. A face detector does not independently establish the emotion
category unless it is specifically trained for that classification task. Face
detection performance also depends on image quality and the model’s
training data.
[12] Bakiasi et al. (2025) presented a real-time micro-expression
recognition system using YOLOv8 and the FER2013 dataset. Their

potential of combining detection and feature-learning techniques.

careful evaluation across different conditions.

2.4 Swin Transformer for Image Classification and Other
Applications
[16] Liu et al. (2021) introduced the Swin Transformer, a hierarchical
vision Transformer that uses shifted-window attention. This design
enables local attention within windows while allowing information
exchange between neighbouring windows across layers. The architecture
was developed as a general-purpose vision backbone and evaluated on
tasks including image classification, object detection, and semantic
segmentation. Its computational requirements and input-resolution
choices must be considered when applying it to facial emotion
recognition.
[17] Cao et al. (2022) proposed Swin-Unet, a U-shaped Transformer
architecture for medical image segmentation. It uses Swin Transformer
blocks in an encoder-decoder structure to learn spatial representations.
The study demonstrated the use of hierarchical Transformer features for
medical-image analysis. However, segmentation of medical images is
different from classifying facial emotions, so the architecture and
training process require adaptation for the proposed project.
[18] Hatamizadeh et al. (2022) presented Swin UNETR for three-
dimensional medical image segmentation. The approach uses a Swin
Transformer encoder to learn representations from volumetric image
data. It illustrates the ability of Transformer architectures to capture
spatial relationships in complex images. Its three-dimensional design

CHAPTER 3
EXISTING SYSTEM AND METHODOLOGY
3.1 General
Facial emotion recognition is a computer vision technique used to
identify human emotions from facial expressions. Existing systems use
image processing, machine learning, and deep learning methods to
classify expressions into categories such as Angry, Disgust, Fear, Happy,
Sad, Surprise, and Neutral. The performance of these systems depends
on image quality, facial feature visibility, and the classification model
used.
3.2 Existing System
Traditional facial emotion recognition systems use handcrafted
features and conventional machine learning algorithms, while more
recent systems use Convolutional Neural Networks (CNNs) to
automatically learn facial features. CNN-based systems can classify
facial expressions effectively but may face challenges when handling
variations in lighting, facial orientation, image quality, and complex
facial patterns.
Some existing approaches perform emotion classification without
integrating a dedicated face detection stage into a complete application
pipeline. This can limit their practical use with images containing
different backgrounds or multiple objects. Therefore, combining reliable
face detection with an effective emotion classification model is
.
important for developing a practical facial emotion recognition system
3.2.1 Drawbacks
•The convolutional receptive field is local, so relationships between
distant facial regions, such as raised eyebrows and an open mouth in
xxiv
---PAGE 25 (988 chars)---
Surprise, are only weakly captured, which caps accuracy at 60–68 % on
FER2013 [2], [3], [4].
•The pipeline presumes an ideal face crop supplied in advance; in
realistic scenes the face must be detected first, and a Haar-cascade front
end produces false positives and unstable crops under pose and
illumination changes.
•The small 48 × 48 grayscale input discards colour and fine detail, and
cannot benefit directly from pre-trained colour backbones, limiting
transfer learning.
•Confusion concentrates in visually similar pairs such as Fear and
Surprise, and in the rare Disgust class, because the model sees few
examples and limited global context.
•Most implementations exist only as training scripts with no service
interface, so integrating the model into an application requires custom
engineering each time.
•There is no mechanism to compare an improved classifier against the
CNN under identical conditions, so claims of improvement cannot be
verified in the deployed pipeline.

4.1 General
The project is implemented in phases, including dataset
preparation, model development, face detection, emotion
classification, system integration, and testing.
4.2 Proposed System
The proposed system integrates YOLOv8 for face detection
with CNN and Swin Transformer models for facial emotion
classification. The FER2013 dataset is used to classify seven
emotion categories. A FastAPI backend and React-based frontend
provide an interface for input processing and displaying predictions.
The system also enables comparison of the CNN and Swin
Transformer approaches based on experimental results.
4.2.1 Advantages
•The YOLOv8 front end removes the dependence on pre-cropped
faces, directly answering the first drawback of the existing system.
•The Swin Transformer captures long-range facial dependencies through
shifted-window attention, addressing the accuracy ceiling of local CNN
receptive fields.
•Both classifiers are evaluated on identical detected faces, giving a
controlled, verifiable comparison that the existing literature lacks.
•All components are open source and run on commodity hardware;
inference on CPU is feasible with the nano variants of YOLOv8.

Purpose: to provide the reference classifier against which the Swin

ABSTRACT
The aim of this project is to develop a NextGen AI Online Exam Cheating
Detection System using Computer Vision and Explainable AI to improve the fairness
and reliability of online examinations. Existing AI-based proctoring systems often
generate false alerts because they identify individual actions without considering the
overall behaviour of students. This creates difficulties for students, faculty members
and educational institutions. To overcome these limitations, the proposed system
integrates real-time webcam and microphone monitoring with context-aware
behavioural analysis. YOLOv8 and MediaPipe are used to detect suspicious objects,
multiple persons, facial orientation, gaze and head movements, while browser
monitoring identifies activities such as tab switching and copy-paste attempts. The
system analyses event confidence, duration and frequency to calculate risk scores and
generate explainable evidence for faculty review. The platform is developed using
React.js, Python, FastAPI and MongoDB, with modules for student authentication,
online examinations, AI monitoring, risk assessment, evidence generation, faculty
review and report generation. The proposed evaluation considers 200 online
examination sessions, comprising 100 genuine sessions and 100 suspicious sessions,
along with 2 baseline approaches for comparison. The target performance is 96.8%
accuracy, 95.9% precision, 96.2% recall and 96.0% F1-score. These values represent
expected targets to be validated through experimental testing, not confirmed results.
The system aims to reduce false alerts and support transparent examination
monitoring. Future enhancements include hardware integration, further testing and
performance optimisation.

CHAPTER 1
INTRODUCTION
1.1 GENERAL
Digital technologies have changed the way educational institutions conduct
assessments. Online examinations are widely used by universities, colleges, certification
programmes and recruitment organisations because candidates can participate remotely. This
flexibility also creates a responsibility to protect examination integrity when candidates are not
physically supervised.
Common examination violations include receiving help from another person, using
unauthorised electronic devices, opening external resources, switching browser tabs and
copying or pasting restricted content. Such activities can affect the fairness of results. Students
may be wrongly suspected, faculty members may need to review long recordings, and
institutions may find it difficult to maintain confidence in remote assessments.
Computer Vision and Artificial Intelligence can assist by analysing webcam images,
facial orientation, objects and activity patterns. However, an isolated action such as looking
away from the screen is not sufficient proof of malpractice. The proposed project, “NextGen
AI Online Exam Cheating Detection System using Computer Vision and Explainable AI”,
combines visual monitoring with browser and audio activity indicators. It evaluates event
confidence, duration and frequency and presents evidence for faculty review [1], [2].
1.2 BACKGROUND OF THE STUDY
Artificial Intelligence (AI) enables computer systems to identify patterns and produce
predictions from data. Computer Vision is the AI field concerned with extracting information
from images and video. In online examinations, these techniques can support face presence
checks, object identification, head-pose analysis and the detection of more than one person in
the camera view.

YOLOv8 (You Only Look Once) is used for object and person detection in video
frames. It returns detected classes, bounding boxes and confidence values. MediaPipe provides
real-time facial landmark information that can support facial orientation, gaze-related analysis
and head-pose estimation. OpenCV is used to capture and prepare webcam frames before they
are passed to the analysis components.
Behavioural analysis examines activities over time rather than treating each
observation independently. Context-aware analysis considers the confidence of an event, how
often it occurs, how long it continues and whether it appears together with other indicators.
Explainable Artificial Intelligence (XAI) presents the event type, timestamp and supporting
information so that the alert can be understood and checked by a human reviewer.
Earlier online-proctoring research has explored YOLO-based object detection, face
landmarks, gaze estimation, head-pose analysis, audio cues and video-based abnormal-activity
classification. The CHEESE framework uses Multiple Instance Learning to consider gaze,
head posture, facial information, body posture and background context. Other studies have
examined behavioural records and multi-camera views. These approaches establish useful
methods, but differences in lighting, camera position, network quality and normal student
behaviour can influence their outputs [2]–[4], [6], [11]–[14].
The project adopts a multi-source approach. Webcam frames are analysed using
OpenCV, YOLOv8 and MediaPipe. Browser events such as tab switching, window-focus
changes and copy-paste actions are separately timestamped. Microphone input is used to obtain
audio activity indicators. The observations are associated with the active examination session
and combined for contextual risk assessment.
The platform is intended to support student authentication, MCQ and programming
examinations, continuous face-presence checks, monitoring, result evaluation, faculty review
and report generation. Automated alerts are treated as indications requiring review, not as final
proof of cheating.

1.3 PROBLEM STATEMENT
Existing online examination monitoring systems may classify normal student activities
as suspicious when they rely on individual visual events. Temporary gaze changes, head
movements, poor lighting or camera repositioning can create false alerts. Systems that provide
only an alert label may also fail to explain what was detected, when it occurred and why it
contributed to a risk classification.
The central problem addressed by this project is the lack of an integrated and
explainable workflow that combines visual observations with browser and audio indicators,
evaluates their context and provides evidence that faculty members can verify. The system
must reduce unnecessary alerts without claiming that automated monitoring can identify every
form of malpractice.
1.4 AIM OF THE PROJECT
The aim is to design a web-based AI online examination monitoring system using
Computer Vision, context-aware behavioural analysis and Explainable AI. It combines
YOLOv8 and MediaPipe visual analysis with supported browser and audio activity
monitoring, calculates configurable risk scores and provides event-based evidence for
authorised faculty review.

1.6 SCOPE AND SIGNIFICANCE
The project scope covers a web application for students and faculty members. Students
can authenticate, select an assigned examination and answer MCQ or programming questions.
Faculty members can view examination sessions, inspect monitoring events, review risk
categories and generate reports. The monitoring inputs are webcam video, microphone activity
indicators, browser events and examination-session information.
The planned evaluation uses 200 examination sessions: 100 genuine sessions and 100
suspicious sessions. The proposed comparison includes an existing AI-proctoring baseline and
a YOLOv8-based detection baseline. Accuracy, precision, recall and F1-score are the primary
evaluation measures. The review target values are 96.8% accuracy, 95.9% precision, 96.2%
recall and 96.0% F1-score; these are targets for validation, not confirmed experimental results.
The system may benefit students by reducing reliance on isolated movements, faculty
members by directing attention to timestamped events, and institutions by providing a common
examination and review platform. Its technical contribution is the combination of multiple
monitoring sources, contextual risk assessment and evidence-oriented explanations.
The system depends on a working webcam, microphone, internet connection and
suitable lighting. Camera quality, background noise, network interruptions and individual
behaviour may affect monitoring. Privacy, access control and responsible retention of
recordings are important. A risk score cannot independently establish misconduct; the final
decision must remain with an authorised faculty member. The present phase covers
requirements, research review, gap analysis, architecture and technology selection.
Implementation, integration and experimental validation are planned for the next phase.

2.1 GENERAL
The literature survey reviews research related to online examination monitoring,
automated cheating detection, computer vision, behavioural analysis, video anomaly detection
and digital proctoring. The selected twenty studies cover screenshot-based monitoring, deep-

2.2 REVIEW OF LITERATURE: ONLINE EXAMINATION MONITORING
Manit Malhotra and Indu Chhabra (2026) [1] presented a decade-long systematic
review of automated online exam proctoring and academic integrity. The authors synthesised
80 peer-reviewed studies published between 2014 and 2024, focusing on machine-learning and
deep-learning methods, system reliability and hardware limitations. The review reports that
CNNs and RNNs can analyse visual cues such as eye movement, head posture and facial
expressions to support automated examination monitoring.
Muhammad Ramzan et al. (2024) [2] investigated pre-trained CNN models for
detecting abnormal activities in online examinations. The researchers extracted motion-based
key frames from exam videos and trained models to classify four common cheating activities.
They created a dataset of examination behaviours and compared different deep-learning
approaches. The YOLOv5 model performed better than the other evaluated pre-trained and
fine-tuned models for unusual-activity detection.

Yemeng Liu et al. (2024) [3] proposed CHEESE, a multiple-instance learning
framework for cheating detection and localisation in online examinations. It combines body
posture and background information with eye gaze, head pose and facial features. A
spatiotemporal graph module analyses changes in these features across video clips.
Experiments on the OEP dataset achieved a frame-level AUC of 87.58%, demonstrating the
value of combining multiple behavioural cues.
Chirag S. Indi et al. (2021) [4] developed an e-exam malpractice detection system using
head-pose and gaze estimation. The system measures a student's visual focus of attention using
webcam video and alerts the examiner when attention moves away from the screen beyond a
predefined threshold. Suspicious video segments are saved for manual review, allowing the
examiner to distinguish possible malpractice from temporary inattention. The reported
attention-classification accuracy was 96.04%.
Chia-Yuan Chuang et al. (2017) [5] studied probable cheating detection using
response-time delay and head pose during online assessments. Their analysis found a statistical
relationship between cheating behaviour, time delay and changes in head orientation relative
to the computer screen. These two measures were used as predictors in a logistic model, which
achieved an average prediction accuracy of 75.6%. The system can flag suspicious behaviour
for review by online exam proctors.
Dilky Felsinger et al. (2024) [6] explored video-based action detection for online exam
proctoring in settings with limited resources. Instead of relying on separately engineered
features, the approach recognises candidate actions directly from webcam recordings. The
study used annotated videos from 24 test-takers performing exam-related actions. Its SlowOnly
deep-learning model achieved a true detection rate of 78.9%, while visual summaries helped
invigilators review recordings faster.
Yuda Sukmana et al. (2025) [7] examined trustworthiness in BYOD online exams
through smartphone screenshots. The study developed an automated screen-capture system for
Android-based learning platforms and compared periodic, event-driven and combined capture
methods. A five-second periodic capture interval was identified as the best configuration. The
collected screenshots were labelled to identify possible dishonest actions such as web
searching, opening webpages and using AI tools.

Shengnan Han et al. (2024) [8] conducted a systematic literature review of digital
proctoring in higher education. Using an adapted PRISMA process and topic modelling, the
authors analysed 154 relevant publications from seven databases. The review identified themes
including cheating detection, student authentication, adoption barriers and student
performance in different proctoring environments. It also discussed implications and future
research needs for digital examinations.
Fakhroddin Noorbehbahani et al. (2022) [9] reviewed research on cheating in online

the literature around motivations, forms of cheating, detection techniques and prevention

dishonesty has been investigated. The review serves as a reference for developing methods to
mitigate, detect and prevent online cheating.
Seife Dendir and R. Stockton Maxwell (2020) [10] examined cheating in online courses

examination monitoring and academic dishonesty in online courses. Its findings provide
evidence relevant to understanding how proctoring records can be used when examining
possible cheating in online assessments. This work supports the importance of evaluating
examination integrity in remotely delivered courses.
Manika Garg and Anita Goel (2023) [11] proposed a machine-learning approach to
preserve integrity in online assessments by analysing student assessment log files. The
researchers engineered thirteen features and compared five classification algorithms with two
feature-selection methods. The Random Forest model using features selected by Mutual
Information achieved about 85% accuracy. The study shows that assessment activity logs can
help identify possible internet-based cheating.
Zuhui Hu et al. (2024) [12] proposed a multi-perspective paperless examination
cheating-detection system based on image recognition. It uses overhead, horizontal and face-
camera views to widen the monitoring area and combines gaze recognition, cheating- tool
detection and behaviour classification. An adaptive selection method reduces processing
requirements while maintaining broad visual coverage. The system achieved 35 frames per
second and an average recognition rate of 95%.

P. Tejaswi et al. (2023) [13] introduced Proctor Net, an AI framework for suspicious-

detect speaking. The framework reported 91% accuracy and generates alerts for the proctor

and blended proctoring than AI proctoring alone.
Bharathkumar Ramachandra et al. (2022) [16] surveyed methods for single-scene video

practices and possible future directions. This survey provides a foundation for analysing
unusual events in video streams.
Huu-Thanh Duong et al. (2023) [17] reviewed deep-learning techniques for anomaly
detection in video surveillance. The study categorises approaches according to their objectives
and learning strategies, and discusses preprocessing and feature-engineering techniques. It also
describes benchmark datasets used to train and evaluate systems that detect abnormal human
behaviour. The review identifies common challenges and future directions for developing more
effective video-analysis methods.

2.3 RESEARCH GAP
Gap 1 – Limited integration of monitoring sources. The reviewed studies examine
different sources, including smartphone screenshots [1], examination video [2], facial and gaze
information [3], [4], [11], [12], audio [12] and assessment logs [10]. These methods are often
developed as separate solutions. The proposed system combines webcam observations with
supported browser events and microphone-based audio activity indicators within a single
authenticated examination session.
Gap 2 – Need for contextual behavioural assessment. Head movement, gaze deviation,
speaking activity or an unusual video event may occur during normal examination behaviour
[4], [5], [11], [12]. Existing studies demonstrate useful detection methods, but individual

indicators may not be sufficient to establish malpractice. The proposed system considers event
confidence, frequency, duration and relationships before assigning a risk category.
Gap 3 – Need for explainable and human-reviewed alerts. Several approaches generate
alerts or identify suspicious video segments [3], [4], [11], while assessment-log and screenshot
methods provide different forms of digital evidence [7], [10]. The proposed platform records
event categories, timestamps, confidence values and supporting evidence so that faculty
members can understand and verify alerts. Automated risk scores are treated as decision-
support information rather than conclusive proof.
Gap 4 – Privacy, usability and practical deployment. Research on student acceptance
identifies the importance of trust and satisfaction [14], while video-anomaly reviews discuss
privacy and deployment challenges [18]–[20]. Multi-camera and deep-learning systems may
also require additional hardware and computational resources [11], [12]. The proposed system
is therefore designed around commonly available webcam and microphone inputs, controlled
access to monitoring records and faculty verification of flagged events.
Overall, the reviewed literature shows that computer vision, deep learning, behavioural
indicators and digital activity records can contribute to online examination integrity. However,
an effective platform must combine relevant monitoring sources, distinguish ordinary
behaviour from potentially suspicious events, explain the basis of alerts and protect student
privacy. These requirements form the foundation of the proposed NextGen AI Online Exam
Cheating Detection System using Computer Vision and Explainable AI.

3.2 EXISTING SYSTEM
The existing system considered in this project is the CHEESE framework proposed by
Yemeng Liu et al. (2024) [3]. It uses Multiple Instance Learning (MIL) to detect and localise
potential cheating activities in online examinations. Rather than classifying only one frame,
the framework analyses groups of visual instances and considers gaze direction, head posture,
facial information, body posture and background context.
The approach uses examination video as its primary input. Relevant frames are
extracted and prepared for visual feature analysis. The extracted characteristics are examined
together so that a sequence of observations can contribute to identifying a suspicious segment.
The resulting locations in the video are then available for examiner verification.
3.2 EXISTING METHODOLOGY
1. Video input collection: examination recordings are obtained from a camera and contain the
student and surrounding environment.
2. Frame extraction and preprocessing: relevant frames are selected and prepared for feature
analysis.
3. Visual feature extraction: facial information, gaze direction, head posture, body posture and
background details are examined.
4. Multiple Instance Learning: groups of visual instances are analysed to learn patterns
associated with possible suspicious activity.

---PAGE 21 (685 chars)---
5. Detection and localisation: potentially suspicious activities and the corresponding video
segments are identified.
6. Output generation: flagged segments are presented for examiner review and verification.
Dataset and Algorithm
The CHEESE framework is described as using the Online Exam Proctoring (OEP)
dataset. Its principal method is Multiple Instance Learning, which aggregates information from
multiple visual indicators. The reported frame-level Area Under the Curve (AUC) is 87.58%.
AUC measures separation across decision thresholds and must not be interpreted as
classification accuracy.

3.2.1 DRAWBACKS
• Limited monitoring sources: the approach mainly analyses examination video and does not
include browser events such as tab switching, window-focus changes or copy-paste actions.
• Possibility of false alerts: normal gaze changes, head movement and posture changes may
be misinterpreted without sufficient context.
• Computational complexity: analysing several visual features with deep-learning methods
may require processing resources that are unavailable on some student devices.
• Limited behavioural context: one indicator may be insufficient; frequency, duration,
sequence and combinations of events should also be considered.
• Limited explainability: a suspicious video segment does not always explain why it was
flagged. Reviewers need timestamps, supporting evidence and understandable risk factors.
• Absence of integrated examination automation: the base approach does not provide a
complete workflow combining authentication, examination management, browser
monitoring, risk assessment and faculty reporting.
These limitations motivate the proposed integration of multiple monitoring sources,
contextual event scoring and explainable evidence generation within a single examination
platform.

4.2 PROPOSED SYSTEM
The proposed platform extends video-only monitoring by combining YOLOv8-based
object and person detection, MediaPipe facial landmark analysis, browser activity monitoring,
microphone-based audio activity indicators, context-aware behavioural analysis and
Explainable AI. React.js provides the user interface, Python FastAPI provides backend
services, and MongoDB stores examination and monitoring records.
Stage 1 – Student Authentication and Examination Input
A student logs in with valid credentials and selects an assigned examination. The
platform displays instructions and requests permission to access the webcam and microphone.
Student details, examination information and a session identifier are associated with the
monitoring session.
Stage 2 – Multi-Source Data Collection and Preprocessing
OpenCV captures and prepares webcam frames. The platform records supported
browser events, including tab switching, window-focus changes and copy-paste actions, and
obtains microphone-based audio activity indicators. Each event is timestamped and associated
with the active examination session.

Stage 3 – Computer Vision Analysis
MediaPipe identifies facial landmarks and supports facial orientation, gaze-related and
head-pose analysis. YOLOv8 detects objects and persons and returns class labels, bounding
boxes and confidence values. A detection is considered when its confidence C meets the
configured threshold C ≥ T_c; the threshold is calibrated during implementation and testing.
Stage 4 – Browser and Behavioural Event Analysis
Visual observations and browser records are converted into categorised events. The
system considers repeated gaze deviations, unusual head movements, additional-person
detection, unauthorised-object detection, face absence, tab switching, window-focus changes
and copy-paste activity. Confidence, frequency, duration and relationships are considered
together.
Stage 5 – Context-Aware Risk Assessment and Explainable AI
A weighted risk score is calculated from detected events. Configurable thresholds
classify the result as Low, Medium or High risk. The XAI component lists contributing event
types, timestamps, confidence information and supporting evidence. Weights, thresholds and
normalisation values are to be calibrated during testing.
Stage 6 – Data Storage, Faculty Dashboard and Reporting
MongoDB stores session details, monitoring events, risk scores and explanations.
FastAPI exposes backend endpoints, and the React.js faculty dashboard retrieves records for
authorised review. Faculty members inspect alerts and evidence and generate monitoring
reports. The final decision remains with the faculty member.

Module 4 – Browser and Behavioural Activity Analysis

Module 5 – Risk Assessment and Explainable AI
Purpose: calculate the examination risk level and provide understandable explanations.
Inputs are categorised events, confidence, frequency and duration. The weighted score is: R =
Σ (wᵢ × cᵢ × fᵢ × dᵢ). Here, wᵢ is the event weight, cᵢ is detection confidence, fᵢ is event frequency
and dᵢ is the duration factor. Low Risk is R < T₁; Medium Risk is T₁ ≤ R < T₂; High Risk is R
≥ T₂. Weights and thresholds are configurable and must be calibrated using test data. XAI
presents the factors that contributed to each alert, along with timestamps and supporting
evidence.
Module 6 – Database, Faculty Dashboard and Report Generation
Purpose: store examination-monitoring information and present it to authorised faculty
members. MongoDB stores student details, examination sessions, event records and risk
assessments. The React.js dashboard retrieves information through FastAPI endpoints and
displays suspicious-activity alerts, explanations and examination records. Faculty members
can review evidence and generate reports. The final decision is made by the faculty member.

5.1 CONCLUSION
The NextGen AI Online Exam Cheating Detection System using Computer Vision and
Explainable AI is proposed to support fair and transparent online examination monitoring. It
combines webcam and microphone inputs, YOLOv8 and MediaPipe visual analysis, browser
activity tracking, context-aware behavioural assessment and evidence-based explanations. The
design addresses limitations of video-only systems by considering multiple sources and
evaluating event confidence, frequency, duration and relationships.
During this phase, the project requirements, problem statement, literature survey,
research gaps, system architecture and workflow were prepared. Six modules were defined:
student authentication and examination management; multi-source data collection and
preprocessing; computer-vision-based face and object detection; browser and behavioural
activity analysis; risk assessment and Explainable AI; and database management with faculty
dashboard and report generation. The selected stack includes React.js, Python FastAPI,
MongoDB, OpenCV, MediaPipe and YOLOv8.
The evaluation plan covers 200 sessions and comparison with two baseline approaches.
The stated values of 96.8% accuracy, 95.9% precision, 96.2% recall and 96.0% F1-score are
targets that remain to be validated. The next phase will implement and integrate the modules,
collect test data, calibrate risk thresholds, evaluate performance and document measured
results. The completed platform is intended to assist faculty members through explainable
alerts and supporting evidence, while the final judgement remains under human supervision.

later review. In the complete system, actual detection modules would generate the events.
from datetime import datetime
import json
event_log = []
def record_event(event_type, details,
risk_level="Medium"):
event = {
"timestamp": datetime.now().isoformat(),
"event_type": event_type,
"details": details,
"risk_level": risk_level
}
event_log.append(event)
print("Event recorded:")
print(json.dumps(event, indent=4))
record_event(
"Multiple Faces",
"More than one face detected",
"High"
)
record_event(
"Looking Away",
"Repeated head movement detected",
"Low"
)
with open("exam_events.json", "w") as file:
json.dump(event_log, file, indent=4)

Appendix B – Context-Aware Risk Scoring Code
The following sample demonstrates a simple rule-based risk scoring method. It
combines event scores to produce a risk category. These example values are illustrative and
must be calibrated and evaluated using actual examination data.
def calculate_risk(events):
score = 0
weights = {
"looking_away": 1,
"multiple_faces": 4,
"unauthorized_object": 3,
"tab_switch": 2,
"face_missing": 3
}
for event in events:
score += weights.get(event, 0)
if score >= 7:
level = "High"
elif score >= 3:
level = "Medium"
else:
level = "Low"
return {
"risk_score": score,
"risk_level": level
}
detected_events = [
"looking_away",
"tab_switch",
"multiple_faces"]
result = calculate_risk(detected_events)
print("Risk Assessment:", result)
